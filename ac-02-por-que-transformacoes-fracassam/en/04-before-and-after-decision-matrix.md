# Before-and-after decision matrix

Map decisions before you map roles. Facilitate with leadership and HR; leadership decides what changes hands.

| Decision | Who decides today | Forum and frequency | Who decides after | Forum and frequency | Tuesday test | Review on |
|---|---|---|---|---|---|---|
| Prioritize what the team does next | | | | | | |
| Accept a delivery | | | | | | |
| Change scope | | | | | | |
| Release to production | | | | | | |
| Start a new initiative | | | | | | |
| Move people between teams | | | | | | |

**Tuesday test:** on any given Tuesday, what does this person do differently from before? If the answer is "nothing", the name changed and the decision did not.

## Illustrative example (Fictional Bank, investments)

| Decision | Before | After | Tuesday test |
|---|---|---|---|
| Prioritize what the team does next | Monthly committee | Product Owner, with quarterly tribe priority review | The PO reorders the backlog without waiting for a meeting |
| Accept a delivery | Project manager, at the end of the project | Product Owner, every increment | Acceptance happens at the increment review |
| Change scope | Change request to the committee | Product Owner, within the agreed goal | Scope change recorded in the backlog the same day |
| Release to production | Monthly window approved by governance | Team, following automated risk criteria | Release when the criteria are met |
