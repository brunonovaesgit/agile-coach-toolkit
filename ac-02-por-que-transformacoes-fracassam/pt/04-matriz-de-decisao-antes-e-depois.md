# Matriz de decisão antes e depois

Mapeie as decisões antes de mapear os cargos. Facilite com a liderança e com RH; a liderança decide o que muda de dono.

| Decisão | Quem decide hoje | Em qual fórum e com que frequência | Quem decide depois | Em qual fórum e com que frequência | Teste da terça-feira | Revisar em |
|---|---|---|---|---|---|---|
| Priorizar o que o time faz a seguir | | | | | | |
| Aceitar uma entrega | | | | | | |
| Mudar o escopo | | | | | | |
| Liberar para produção | | | | | | |
| Iniciar uma nova iniciativa | | | | | | |
| Remanejar pessoas entre times | | | | | | |

**Teste da terça-feira:** numa terça qualquer, o que essa pessoa faz de diferente do que fazia antes? Se a resposta for "nada", o nome mudou e a decisão não.

## Exemplo ilustrativo (Banco Fictício, investimentos)

| Decisão | Antes | Depois | Teste da terça-feira |
|---|---|---|---|
| Priorizar o que o time faz a seguir | Comitê mensal | Product Owner, com revisão de prioridades da tribo a cada trimestre | O PO reordena o backlog sem esperar reunião |
| Aceitar uma entrega | Gerente de projeto, ao fim do projeto | Product Owner, a cada incremento | Aceite acontece na revisão do incremento |
| Mudar o escopo | Pedido de mudança ao comitê | Product Owner, dentro do objetivo combinado | Troca de escopo registrada no backlog, no mesmo dia |
| Liberar para produção | Janela mensal aprovada pela governança | Time, seguindo critérios automatizados de risco | Liberação quando o critério é atendido |
